# Database Design

## Database

MySQL 8.x is the recommended local database baseline. Pin the exact
tested version in project documentation.

Use SQLAlchemy models and Alembic migrations. Do not manually edit
production schemas.

## Core tables

### users

``` text
id BIGINT PK
email VARCHAR(255) UNIQUE
name VARCHAR(255)
password_hash VARCHAR(...)
status VARCHAR(32)
created_at DATETIME
updated_at DATETIME
```

### projects

``` text
id BIGINT PK
user_id BIGINT FK
name VARCHAR(255)
description TEXT
source_type VARCHAR(64)
status VARCHAR(32)
created_at DATETIME
updated_at DATETIME
```

### collection_configs

``` text
id BIGINT PK
project_id BIGINT FK
provider VARCHAR(64)
config_json JSON
version INT
is_active BOOLEAN
created_at DATETIME
updated_at DATETIME
```

The JSON contains provider-specific configuration while stable,
queryable fields should be promoted to columns when necessary.

### jobs

``` text
id BIGINT PK
project_id BIGINT FK
config_id BIGINT FK
status VARCHAR(32)
requested_at DATETIME
started_at DATETIME NULL
finished_at DATETIME NULL
total_units INT
successful_units INT
failed_units INT
skipped_units INT
records_created INT
records_updated INT
records_rejected INT
error_code VARCHAR(64) NULL
error_message TEXT NULL
```

### job_runs

``` text
id BIGINT PK
job_id BIGINT FK
worker_id VARCHAR(128)
status VARCHAR(32)
started_at DATETIME
finished_at DATETIME NULL
heartbeat_at DATETIME
attempt INT
metrics_json JSON
```

### records

``` text
id BIGINT PK
project_id BIGINT FK
job_id BIGINT FK
provider VARCHAR(64)
provider_record_id VARCHAR(255) NULL
canonical_key VARCHAR(512)
data_json JSON
collected_at DATETIME
created_at DATETIME
updated_at DATETIME
```

`canonical_key` is generated by deterministic normalization and is
indexed/unique at the appropriate project scope.

### record_provenance

``` text
id BIGINT PK
record_id BIGINT FK
source_reference TEXT NULL
provider_operation VARCHAR(255)
collected_at DATETIME
metadata_json JSON
```

Only retain source information that the provider terms and applicable
privacy rules permit.

### exports

``` text
id BIGINT PK
project_id BIGINT FK
requested_by BIGINT FK
format VARCHAR(32)
status VARCHAR(32)
filters_json JSON
file_path VARCHAR(1024) NULL
created_at DATETIME
completed_at DATETIME NULL
```

### schedules

``` text
id BIGINT PK
project_id BIGINT FK
cron_expression VARCHAR(255)
timezone VARCHAR(64)
enabled BOOLEAN
next_run_at DATETIME
last_run_at DATETIME NULL
```

### audit_logs

``` text
id BIGINT PK
user_id BIGINT NULL
action VARCHAR(128)
entity_type VARCHAR(64)
entity_id BIGINT NULL
details_json JSON
created_at DATETIME
```

## Index strategy

At minimum:

-   projects(user_id, status)
-   collection_configs(project_id, is_active)
-   jobs(project_id, status, requested_at)
-   job_runs(job_id, status)
-   records(project_id, canonical_key)
-   records(project_id, collected_at)
-   exports(project_id, created_at)
-   schedules(enabled, next_run_at)
-   audit_logs(user_id, created_at)

Do not add indexes blindly. Verify with query plans.

## Migration rules

1.  Every schema change gets an Alembic migration.
2.  Migrations must be reversible where practical.
3.  Never delete data as part of an unrelated migration.
4.  Seed only deterministic development data.
5.  Test migrations from an empty database and from the previous schema.
